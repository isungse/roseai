# i18n (한국어 고정)

`next-intl` 기반. 사이트는 **한국어 하나**만 제공한다 — 로케일 라우팅·로케일 세그먼트·언어 토글이 없다.

이유: 제품 소개 사이트로 개편하면서 영어판을 만들지 않기로 했다(오너 결정, 2026-10-28). 문구를 메시지 JSON에 모으는 규칙은 그대로다 —
하드코딩을 막고, 문구 확정·되돌리기(work-log)를 파일 하나에서 하기 위해서다.

## 구조

```
messages/
  ko.json               # 메시지 파일 하나
i18n/
  request.ts            # getRequestConfig — locale "ko" 고정, ko.json 로드
next.config.ts          # createNextIntlPlugin("./i18n/request.ts")
app/
  layout.tsx            # <html lang="ko"> + NextIntlClientProvider
```

`[locale]` 세그먼트, `i18n/routing.ts`·`i18n/navigation.ts`, `proxy.ts`(next-intl 미들웨어)는 두지 않는다.
**확장 지점**: 언어를 다시 더하려면 next-intl 라우팅(`defineRouting` + `createNavigation` + proxy + `[locale]` 세그먼트)을 되살리고,
메시지 파일 간 키 트리 동일 규칙을 다시 세운다 — 2026-10-28 이전 git 이력에 두 언어 구성이 있다.

## 번역 키 규칙

- 네임스페이스는 **섹션 또는 컴포넌트 단위**. 현재: `common`, `footer`, `notFound`, `works`(제품 문구 전부 — `works.meta`·`works.hero`·`works.features.<slug>`·`works.tour` …).
- 키는 dot.camelCase. 공백·하이픈·대문자 금지.
- 같은 문구라도 맥락이 다르면 키를 분리한다. "제출" 버튼과 "제출" 폼 타이틀은 다른 키.
- 플레이스홀더는 ICU MessageFormat: `"hello": "안녕하세요 {name}님"`.
- 복수형은 ICU plural: `"items": "{count, plural, =0 {항목 없음} other {#개 항목}}"`.
- 배열 값(예: `works.values.<zone>.items`)은 `t.raw()` 로 읽는다.
- 선택 키는 `t.has(key)` 로 감지해 렌더를 분기한다. 빈 문자열로 자리만 채우지 않는다.

## 데이터 상수 vs 번역 텍스트 분리

번역 가능한 텍스트는 `messages/ko.json` 에, 번역 불변 메타는 `lib/data/*.ts` 에 둔다.

```ts
// lib/data/works.ts
export const WORKS_FEATURES = [
  { slug: "approval", icon: FileSignature, tabs: [/* … */] },
  // …
] as const;
```

```json
// messages/ko.json
{ "works": { "features": { "approval": { "name": "전자결재", "tagline": "…" } } } }
```

원칙:
- `slug`, 아이콘, 이미지 경로, 사이트 경로(`featureHref`·`TOUR_HREF`), 숫자값은 데이터 상수.
- `title`, `tagline`, `body` 등 사람이 읽는 문자열은 JSON.
- 디자인 요소 — 로고의 `WORKS`, 제품명 `ROSE-AI WORKS`(`WORKS_PRODUCT_NAME`), 영문 캡션 같은 표기 — 는 **디자인이지 번역 대상이 아니다.** 상수로 둔다.

## 하드코딩 금지

- JSX 안의 사용자 노출 텍스트는 전부 `useTranslations()` 또는 `getTranslations()` 를 통과해야 한다.
- 로그/콘솔/에러 메시지(개발자용)는 예외 — 하드코딩 허용.
- `aria-label`, `title`, `alt` 도 메시지 키로 둔다.

## 멀티-라인 본문 값

본문이 여러 줄로 나뉘어 보여야 하면 JSON 값에 `\n` 을 넣고 렌더 컴포넌트에 `whitespace-pre-line` 을 적용한다.

```json
"lead": "첫 번째 문장.\n두 번째 문장."
```

```tsx
<p className="whitespace-pre-line">{t("lead")}</p>
```

`whitespace-pre-line` 은 `\n` 만 줄바꿈으로 렌더하고 들여쓰기 공백은 collapse — 단락 구조만 살린다. 단락을 시각·의미적으로 완전히 나눠야 하면
배열로 모델링하고 `<p>` 를 여러 개 렌더하는 쪽이 더 명확하다.

## 링크

- 내부 링크는 `next/link`, 현재 경로는 `next/navigation` 의 `usePathname`. 로케일 접두어가 없으므로 next-intl 래퍼를 쓰지 않는다.
- 경로 문자열은 컴포넌트에 흩어 두지 않고 `lib/data/works.ts` 의 헬퍼로 만든다.

## 정적 자산 URL

Next 16 의 정적 핸들러는 **디렉토리 인덱스를 자동 해석하지 않는다** (`/foo/` → `/foo/index.html` 자동 매핑 없음).

- `/public/` 정적 자산을 링크할 때는 **URL 에 확장자를 명시**한다 (`/demos/works/dashboard/index.html`).
- 디렉토리 형태 URL 이 꼭 필요하면 `next.config.ts` 의 `rewrites()` 로 매핑한다.
- 브라우저는 308 Permanent Redirect 를 강하게 캐시한다. 잘못된 리다이렉트가 한 번 캐시되면 설정을 고쳐도 사용자 측에서 재현될 수 있다 —
  디버깅 시 hard reload (`Ctrl+Shift+R`) 나 새 프로필로 먼저 확인한다.

## 메타데이터

- `generateMetadata` 안에서 `getTranslations(namespace)` 로 제목/설명을 가져온다. hreflang 은 두지 않는다 (seo.md).

## 날짜·숫자·통화

- `next-intl` 의 `useFormatter()` 사용. `toLocaleString` 직접 호출 금지.
- 통화 KRW, 시간대 Asia/Seoul 기준. UTC 저장·표시 시 변환.
